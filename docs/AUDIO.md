# 录音降噪与音量

应用现在可在本机使用 RNNoise 0.2+ 处理录音。普通听写与实时听写共用同一段增强后的音频；导出历史录音也会是实际送入 ASR 的版本。原有历史记录和手动导出的原文件不会自动修改。

```toml
[audio]
input_device = "" # 保留自己的设备选择
noise_suppression = true
input_gain_db = 0.0
denoise_mix = 0.85
```

程序默认关闭降噪、增益为 0 dB，以保持旧配置的行为。`input_gain_db` 只适合补偿低电平输入，并不能单独提高信噪比；不要将本机示例的 24 dB 套到所有麦克风。突然出现的强声音会经过峰值保护，避免增益直接造成满幅削波。

`denoise_mix` 是降噪信号的混合比例。默认 0.85 保留 15% 对齐原声；1.0 抑噪更强，也可能丢失弱音。RNNoise 无法保证恢复已经被噪音掩盖的说话声，也不一定能消除其他人的讲话声。遇到吞字、金属音，先降低混合比例或关闭降噪对比，并检查麦克风距离和采集设置。

## 麦克风测试窗口

在托盘或 Waybar 右键菜单选择「麦克风测试…」，打开独立窗口。打开窗口时不自动开启监听，点击「开始监听」后才打开音频设备。建议佩戴耳机，监听音量默认 20%，避免扬声器回授。

窗口提供输入设备和监听输出选择、原始／处理后电平、输入增益、RNNoise 开关、降噪混合比例和监听音量。修改参数会在约 150 ms 的拖动防抖后用于试听；增益、混合比例与监听音量更新时保持音频流运行，切换设备或降噪模式可能有短暂停顿。

- 「保存设置」只保存输入设备和录音处理参数，并应用于之后的听写。
- 输出设备和监听音量只用于本次测试，不改变录音配置或系统音量。
- 「恢复已保存」恢复当前窗口上一次保存的录音参数；关闭窗口不保存其他未确认修改。
- 「停止监听」或关闭窗口释放输入、输出设备。窗口打开期间不能同时开始听写或历史重处理，避免设备争用。

监听只在本机处理和播放，不调用 ASR／LLM，不生成录音文件，也不写入听写历史。实际延迟取决于设备缓冲、系统音频服务和降噪；缓冲区有上限，输出滞后时丢弃旧试听帧以避免积压。

## 安装

Arch Linux：

```bash
sudo pacman -S rnnoise
uv pip install --python .venv/bin/python -e '.[audio-enhancement]'
```

其他平台需要能被系统动态库搜索路径发现的 RNNoise 0.2+；缺失时会给出明确错误。关闭降噪只调增益不需要该库。重采样使用 soxr，`.[realtime]` 已包含它。RNNoise 使用本机系统库的默认模型，无需下载大型权重，也不使用 GPU。每次录音创建独立状态，结束或异常后释放。

首次更新代码后重启应用。以后改配置可通过菜单「重新加载配置」，从下一次录音开始生效；不会在一句话中间重置降噪状态。

## 实现与延迟

音频回调只把输入帧放入有界队列，录音工作线程负责处理。先调整输入增益，再在 48 kHz 上以 10 ms 帧运行 RNNoise，补偿 0.2 版本的 20 ms 前视／合成延迟，使降噪信号与原声混合时对齐。停止时排空剩余输入并刷新重采样器、降噪器，保留尾音。实际实时延迟还包括约 100 ms 的采集块及识别服务延迟。

处理后的音频一份用于历史保存，一份重采样成 ASR 需要的 16 kHz PCM。文件重转写不会自动再次降噪历史音频，避免重复处理。

## 处理已有录音

下面的命令只在本机生成新文件，不上传到模型服务，也不覆盖原文件或已有输出：

```bash
.venv/bin/python -m asr_evo.cli.enhance_audio input.wav enhanced.wav --gain-db 24 --mix 0.85
# 相同增益但不降噪，用来公平对比
.venv/bin/python -m asr_evo.cli.enhance_audio input.wav gain-only.wav --gain-db 24 --no-denoise
```

本次用户样本约 140.72 秒，原始整体 RMS 约 −60.5 dBFS，没有削波。采用 +24 dB 和 0.85 混合比例后，输出 RMS 约 −37.8 dBFS、峰值约 −4.8 dBFS。与仅增加相同音量的版本相比，能量最低的 20% 片段下降约 15.9 dB，能量最高的 20% 片段整体电平变化约 −0.6 dB。本机处理整段约耗时 0.83 秒，处理前后时长一致。

这些测量没有干净的人声参考，不能解释成真实信噪比改善或转写准确率提升。试听文件和测量说明保存在本机 `artifacts/audio-comparison/`，该目录已排除出 Git。

参考：[RNNoise 官方项目](https://github.com/xiph/rnnoise)。

## 偶发录音溢出

听写采集使用 PortAudio 的高稳定性缓冲（`latency="high"`），麦克风测试监听仍采用低延迟输出。设备偶发报告 `input_overflow` 时，程序保留当前缓冲的有效音频并继续录音，结束后在日志中汇总次数；已经被设备丢弃的片段无法恢复。该通知不会再直接触发整次听写失败。如果应用内部的有界处理队列填满，仍会停止并报告「音频处理积压」，避免无限堆积或静默丢弃输入。
